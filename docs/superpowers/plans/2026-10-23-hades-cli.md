# Hades CLI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the `hades` binary: `up`/`down` and their helpers that turn a git worktree of any project into a running dev environment on a dev server or a laptop, as specified in the CLI design.

**Architecture:** One Go module `github.com/quotedo/hades` with a thin stdlib-`flag` dispatcher in `cmd/hades` and focused packages under `internal/`: pure naming and config logic first, then the registry (ports, manifests), environment files, Postgres/RabbitMQ/Caddy/MCP adapters behind small interfaces, and finally the `up`/`down`/`gc` orchestration that composes them. Every external command runs through one `execx.Runner` so tests substitute a recording fake and `--dry-run` prints instead of running.

**Tech Stack:** Go 1.25 (no CGO), `github.com/BurntSushi/toml`, `github.com/jackc/pgx/v5`, standard library for everything else; goreleaser for releases; GitHub Actions on `ubuntu-latest` and `macos-latest` (arm64) with a Postgres 17 service on Linux.

**Spec:** `/Users/roman/Projects/hades/docs/superpowers/specs/2026-10-23-hades-cli-design.md` (companion: `2026-10-23-hades-server-design.md` for the host side).

## Global Constraints

- Platforms: darwin/arm64 and linux/amd64 are first class and run in CI; linux/arm64 and darwin/amd64 are built, labelled untested; nothing else.
- Dependencies: exactly `github.com/BurntSushi/toml` and `github.com/jackc/pgx/v5` (plus their transitive deps); no CLI framework; `CGO_ENABLED=0`.
- Human output to stderr; `--json` results to stdout; exit codes 0 success, 1 failure, 2 usage.
- `up` is idempotent; a failure in steps 1–9 rolls back what this run claimed; a failure from the project's setup on keeps everything and exits 1. `down` exits 0 unless `--strict`, printing one line per skipped or failed step.
- Never act on a manifest not owned by the invoking user (except `gc` as root); never drop a database that does not match the manifest's recorded prefixes and suffix; never modify tracked files other than the MCP configs; never run `git commit`, `git push`, or change branches.
- Label: `label_template` default `{{project}}-{{name}}`, rendered label ≤ 63 chars, project slug ≤ 30 chars; `DB_SUFFIX` = `_<user>_<name>`, `-`→`_`, only `[a-z0-9_]`, ≤ 32 bytes with the `23 + "_" + 8 hex sha256` rule.
- Site file grammar: exactly one line `import worktree <host> <port>` matching `^import worktree [a-z0-9.-]+ [0-9]+$`.
- Host config path `/etc/hades/host.toml` (override `HADES_HOST_CONFIG`); laptop registry `~/.local/state/hades`; laptop defaults port range `4100-4999`, Postgres `127.0.0.1:5432` `postgres`/`postgres`, overridable by `HADES_PORT_RANGE`, `HADES_DB_PORT`, `HADES_DB_USER`, `HADES_DB_PASSWORD`.
- Hooks run with a bare PATH: project commands get `$HOME/.asdf/shims` and `$HOME/.local/bin` (when they exist) plus host `tool_paths` prepended.
- Commit after every task; conventional one-line subjects; `gofmt`, `go vet` and `go test ./...` clean before each commit.

## Review Focus

1. A worktree name with no usable characters (`"???"`) or a project slug over 30 chars: `up` exits 1 with a message naming the input, never panics. Pinned in Task 2.
2. Two `up` runs racing for ports: twenty concurrent claims get twenty distinct, lowest-first ports. Pinned in Task 6.
3. A developer's own lines in `.envrc` outside the managed block survive `up` byte for byte, and a second `up` leaves the file unchanged. Pinned in Task 7.
4. `down` run by a different user, or from a worktree path with no manifest, prints why and exits 0 touching nothing. Pinned in Task 12.
5. A manifest recorded with prefixes `["gym_nation"]` while the current `hades.toml` says `["other"]`: `down` drops by the manifest, not the file. Pinned in Task 12.

### Task 2: Naming: sanitise, slug, label template, DB suffix

**Files:**
- Create: `internal/naming/naming.go`, `internal/naming/naming_test.go`

**Interfaces:**
- Produces:
  - `func Sanitize(s string) string` — lower-case; every run of characters outside `[a-z0-9]` becomes one `-`; leading/trailing `-` stripped.

  - `const DefaultLabelTemplate = "{{project}}-{{name}}"`

### Task 4: Command runner and context resolution

**Files:**
- Create: `internal/execx/execx.go`, `internal/execx/execx_test.go`, `internal/wtctx/wtctx.go`, `internal/wtctx/wtctx_test.go`, `internal/testutil/testutil.go`

**Interfaces:**
- Produces (`execx`):
  - `type Cmd struct { Argv []string; Dir string; Env []string; Stdin io.Reader }`
  - `type Result struct { ExitCode int; Stdout, Stderr string }`
  - `type Runner interface { Run(ctx context.Context, c Cmd) (Result, error) }` — a non-zero exit is returned as `*ExitError{Cmd, Result}` (so callers distinguish "failed" from "could not start").
  - `type Real struct { Prepend []string; Log io.Writer }` — runs with `exec.CommandContext`; `Env` fully replaces the environment when non-nil, else inherits; `PATH` gets `Prepend` entries that exist on disk prepended.
  - `func ToolPrepend(home string, extra []string) []string` — `home/.asdf/shims`, `home/.local/bin`, then `extra`.
  - `type Fake struct { mu sync.Mutex; Calls []Cmd; Handle func(Cmd) (Result, error) }` — records every call; default handler returns exit 0.
  - `type DryRun struct { Out io.Writer; Next Runner }` — prints `would run: <argv> (in <dir>)` and returns exit 0 for commands that mutate; the orchestration passes read-only commands (`git rev-parse`) to `Next`.
- Produces (`wtctx`):
  - `type Context struct { Root, Worktree, Name, ADE string }`
  - `type Flags struct { Root, Worktree, Name, ADE string }`
  - `func Resolve(ctx context.Context, f Flags, getenv func(string) string, cwd string, run execx.Runner) (Context, error)` — per value: flag, then Paseo env (`PASEO_SOURCE_CHECKOUT_PATH` or `PASEO_ROOT_PATH`, `PASEO_WORKTREE_PATH`, `PASEO_BRANCH_NAME`), then Orca env (`ORCA_ROOT_PATH`, `ORCA_WORKTREE_PATH`, `ORCA_WORKSPACE_NAME`), then git (`git -C cwd rev-parse --show-toplevel`, `git -C cwd rev-parse --git-common-dir` → its parent after `filepath.Abs`, `git -C cwd branch --show-current`, falling back to `filepath.Base(worktree)` when detached). `ADE` is `"paseo"`, `"orca"`, `"wt"` when `--ade` says so, else whichever env family supplied a value, else `"shell"`. `--ade` restricts env reading to that family. All paths returned through `filepath.EvalSymlinks` when they exist.
